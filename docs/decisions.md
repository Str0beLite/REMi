# Decisions

One line each: date, decision, why.

- 2026-11-07: Own Python OpenClaw-style runtime, not OpenClaw: small prompts for a 4B, our chat template (the LoRA transfers), and no experimental channel-plugin API.
- 2026-11-07: Base model Nemotron 3 Nano 4B in vLLM, text tool calls (one slash command per turn): the most reliable on a small model, and it matches the pilot.
- 2026-11-07: SpacetimeDB (TypeScript module, Maincloud) holds all shared state: one source of truth, and the UI gets live subscriptions.
- 2026-11-07: The Python runtime talks to SpacetimeDB over HTTP + 1s SQL polling, because there is no Python SDK.
- 2026-11-07: Agents are user-defined YAML Agentfiles; Sleep REMi is the only built-in agent. Nothing is hard-coded per persona.
- 2026-11-07: Tools are human-approved (dry-run card) and shared to every REMi, so the model never ships unreviewed code.
- 2026-11-07: Sleep REMi decides when and what to train using tool calls; the runtime enforces hard guardrails; there is human rollback.
- 2026-11-07: Sleep REMi is protected (it can't attach adapters to itself, admin only), so a bad LoRA can't corrupt the judge.
- 2026-11-07: Adapters are named and versioned; each agent mixes them with weights, merged and hot-loaded into vLLM. No monolithic model.
- 2026-11-07: Datasets and adapters live on the node's disk with metadata in SpacetimeDB; HF Hub sharing is a stretch goal.
- 2026-11-07: Incidents, a second node, the LoRA library and external channels are extensions, not core.
- 2026-11-07: Claude copy of grilling uses AskUserQuestion for each round (installer patches it with --claude).
- 2026-11-07: Parallel build runs as 3 lanes (web/core/gpu, ≤2 sessions each) over GitHub issues; a task is done when its PR merges; coordination skills live in kit/skills.
- 2026-11-07: Contract enums are plain strings validated in reducers (not SpacetimeDB sum types) so the Python runtime reads/writes plain JSON.
- 2026-11-07: Name+version tables (tool, adapter) use an extra unique `key` = "name@version" column; SpacetimeDB primary keys are single-column.
- 2026-11-07: Agentfile and train spec are JSON Schemas in contract/, validated by both the module (ajv) and the runtime (jsonschema).
- 2026-11-07: Stack pinned: spacetimedb 2.14.0 (module + frontend), Vite 7 + React 19, Python 3.12 + uv; module tests use spacetimedb's in-process test harness, so CI needs no spacetime CLI.
- 2026-11-07: Added stack skills per lane (official SpacetimeDB TS server/client/concepts/cli, community SpacetimeDB HTTP/SQL/serialization, HF trl-training, Vercel react-best-practices); installer fetches sparsely.
- 2026-11-07: Frontend stays a web console (config page + multi-channel chat), not a native app; vLLM needs Linux/WSL2 anyway, and the demo opens on a phone.
- 2026-11-07: Node setup is `remi up` (Docker Compose: official vLLM image + runtime/trainer image + sandboxes, restarts on boot), issue #29. Tray app is a stretch goal; Discord mirroring stays extension 4.
- 2026-11-07: Team is all on Claude Code: installer enables the full Ponytail plugin in .claude/settings.json, installs son-wtf by default, drops the Supabase option (SpacetimeDB only), and runs on Windows Git Bash and macOS without python3.
- 2026-11-07: Simar's "Memories and Knowledge Connectors" doc is read with incidents = ordinary user chats; the core doesn't change. Episode cards, playbooks, retrieval/embeddings, system map, log baselines, knowledge connectors, remi-shell and the voice note are out of scope.
- 2026-11-07: Memory is strictly per agent (/note). Sharing is always a message (DM, channel, or a new channel via /channel new) or the shared file workspace; there's no shared memory pool.
- 2026-11-07: The prompt has a hard token budget (setting context_tokens, ~4k) filled by recency: purpose + tools, newest notes (~400 tokens), then recent messages. A 4B model does badly with long, noisy context.
- 2026-11-07: Multi-PC swarm keeps the term "node" (one PC = one runtime + one vLLM); many agents per node, each pinned by `agent.node_id`, re-pinned with `move_agent`. Sleep is per node, so other PCs stay awake.
- 2026-11-07: An agent's Nemotron version is an Agentfile `base` field from a fixed `BASE_MODELS` list (BF16 nemotron_h only); it must equal its node's base, so adapter.base = agent base = node base.
- 2026-11-07: Adapters attach only on the node that trained them (files are local); agents with adapters can't move. Relaxed with the LoRA library (extension 3).
- 2026-11-07: New PCs join with an admin-set `node_join_code` passed to `register_node`; this settles the node half of the admin-bootstrap question.
- 2026-11-08: Mascot direction is "Lavender & plum" (the ChatGPT spec palette, light + dark), on an SVG rig whose actions map to agent statuses and message kinds; mockups in docs/design/remi-character-studio.html.
- 2026-11-08: Web app look is "Rack elevation": plum channel rail, chat centre, and a right Swarm rail drawing each node as a U-numbered rack with REMis as unit plates; sketch in docs/design/app-directions/rack-elevation.html.
- 2026-11-08: Lane work skips PRs: agents rebase, run checks, push straight to main and close the issue with evidence. Contract changes stay Ryan-only.
- 2026-11-08: GPU stack is an optional `gpu` extra in backend/runtime (vllm 0.33.0, peft 0.21.2, transformers 5.20.2, Linux only); vLLM runs at --gpu-memory-utilization 0.85 and --max-lora-rank 64 (= training guardrail); runtime LoRA loading verified on nemotron_h (#23).
- 2026-11-08: Tools stay on our text grammar (built-ins, sandbox `/sh`, admin-approved registry tools) as the main path. An MCP layer comes later on top: the runtime is the MCP client (secrets stay out of sandboxes), agents get a short allowlist of MCP tools through the same dispatch, remote servers only, and Composio is one MCP server, mainly for per-user OAuth apps.
- 2026-11-08: CI installs a `cpu` extra (CPU-only torch from the PyTorch CPU index + transformers/peft/trl/datasets) so the trainer's CPU test runs in CI; `cpu` and `gpu` extras conflict (#24).
- 2026-11-08: Adapter mixes are merged straight from the LoRA files (stack A/B with weights and scales folded in = PEFT `cat`, exact; past rank 64 an exact low-rank SVD cuts back to 64), so no base model is loaded and a mix change takes under a second (#25).
- 2026-11-08: Agent turns run at temperature 0 and end a run after the same failure twice; new built-in `/think` makes one thinking-on call (temperature 0.6) on the agent's own adapter mix, so adapters can shape reasoning (CoT training: #61).
- Contract issues that block a lane are landed by the contract-approver subagent (.claude/agents/contract-approver.md) under Ryan's standing approval (2026-11-08); only exact, additive changes, anything else gets needs:ryan.
- 2026-11-08: One SpacetimeDB workspace per install: `remi up` runs its own SpacetimeDB, publishes the module and makes the publisher admin (browser gets admin from a one-time claim link); the Maincloud `remi` DB is only the team demo (#64, #65, #66). New label `priority:high` makes `/lane` pick an issue first.
- 2026-11-08: A node is one container: official vllm/vllm-openai image + runtime/trainer, with the runtime owning vLLM as a child process (as on the hand-set-up PC), so the sleep cycle's stop/start works unchanged; sandboxes are sibling containers via the Docker socket (#29). Replaces the separate vLLM container in the 2026-11-07 line.
- 2026-11-08: CoT training data (#61): the first lab run uses GSM8K (`openai/gsm8k`, MIT, not gated), worked steps as `reasoning` and the `####` number as the answer, because every answer is checkable. `nvidia/Nemotron-Post-Training-Dataset-v2` is gated (an HF token that accepted its terms on the node), so it comes second. Traces for REMi's own tasks from a bigger LLM (Composio) wait until the lab shows CoT adapters help.
- 2026-11-08: Incidents enter through a localhost HTTP intake on the runtime (`POST /incident` → `#incidents` as system), not a new reducer, so any local app can raise one and the module only gains constants (#67).
- 2026-11-08: Agents can move between nodes (#76): the Agentfile and memories are already in SpacetimeDB, and LoRA dirs travel tarred through `blob_chunk`, with the cutover done in one `finish_migration`. A LoRA shared with an agent that stays behind is copied (`adapter_copy`). This replaces "agents with adapters can't move" without the HF LoRA library. The sandbox stays on the node. `/send` puts a file in another agent's `/shared` and @mentions it (#77). `/agents` stops and starts REMis (#79). `blob_chunk` is public: nodes have their own identities, so a private table would only reach the owner's node.
- 2026-11-08: Drop Maincloud. Every workspace is its own SpacetimeDB on its own hardware (`remi up`); other machines and browsers reach it directly over whatever network connects them (`remi up --lan`, `remi join`); nothing is VPN-specific, and the join command uses the address the admin opened the console with. Companies run their own infra. The console's default is the page's own host (#87).
- 2026-11-08: One `remi up` for every machine. Each runs its own SpacetimeDB, console and node, listening on the network; the printed link opens an onboarding that starts a new cluster or joins one by pasting a join link from the cluster's console (Config > Add a machine). Joining goes through the node's `/setup/` endpoint behind the console, proven by `up`'s one-time code; every machine's console then connects to the cluster's database, so any machine's web UI is a way into the whole cluster (#83). `remi join` and `--lan` are gone.
- 2026-11-08: Console uploads and sandbox browsing go through SpacetimeDB like everything else (#98, #99). An upload is a `/send` from a person (`send_file` with from_agent 0, the browser putting the chunks itself), so delivery to `/shared` is the one existing path. Browsing is request/response rows (`fs_ask` → `fs_request` → `fs_answer`): the agent's node runs a fixed `python3 -I` script inside the sandbox that resolves paths there, so `..` and symlinks can't leave `/workspace` and `/shared`. Reads stop at 1 MB; rows are public (nodes have their own identities) and live 10 minutes.
